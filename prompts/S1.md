## 1 — Accessors and the three traversals

> Load `skills/scheme-dev/SKILL.md` and follow it, especially the whitelist in
> section 2 and the note about `'()` in section 4.
>
> One unit of work: the tree accessors and the three traversal helpers for S1.
> Do not write the printing functions or the height/leaf functions yet.
>
> `code/63_q3.rkt` starts with `#lang racket/base` and contains definitions
> only. A binary tree is `'()` or `(value left right)`.
>
> Define `node-value`, `node-left`, `node-right` and `leaf?`, then define three
> helpers that build the inorder, preorder and postorder value lists in
> accumulator-passing style — each takes the tree and the list to prepend onto,
> and returns the traversal followed by that list.
>
> `append` is forbidden and would be quadratic here anyway, so build the result
> in one pass with `cons` and the accumulator. For each helper give a header
> comment with the contract, a one-sentence statement of *what the result is*
> (not what the steps are), and the base case, recursive case and measure.
>
> `leaf?` must be false for the empty tree. Write it without using the boolean
> literals `#t`/`#f`, since they are not on the whitelist — `and` and `not` are.
>
> Do not call anything at the top level.

## 2 — Height and leaf count

> Next unit: the two shape measurements only.
>
> Define `tree-height` — the empty tree has height 0, a node is 1 plus the
> larger of its subtree heights, so a single node has height 1 — and
> `leaf-count`, the number of nodes whose two subtrees are both empty, with the
> empty tree having none.
>
> Use `max` for the height. Use `cond` with `else` for the three leaf cases.
> Reuse the accessors and `leaf?` from the previous unit rather than writing
> `cadr`/`caddr` again.

## 3 — S1.a, S1.b, S1.c, the printing functions

> Next unit: the three functions the grader actually calls.
>
> - `(print-inorder tree)` prints the inorder value list on one line.
> - `(print-all-traversals tree)` prints three lines: inorder, then preorder,
>   then postorder.
> - `(print-height-and-leaves tree)` prints the two-element list
>   `(height leaf-count)` on one line.
>
> Each uses `display` and ends its output with a newline, and prints nothing
> else: no label, no prompt, no trailing space. `displayln` is not on the
> whitelist. Keep these as thin wrappers over the helpers already written.
>
> Then check against every example in the assignment. For
> `t1 = (4 (2 (1 () ()) (3 () ())) (6 (5 () ()) (7 () ())))`,
> `t2 = (1 () (2 () (3 () ())))`, `t3 = (a (b () ()) (c () ()))` and the empty
> tree, run the file the way the grader does — append the calls to a copy of the
> file and run `racket` on it — and show me the exact output. Also show me that
> running `racket code/63_q3.rkt` on its own prints nothing at all.
